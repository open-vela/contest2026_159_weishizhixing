# 见微·随身证：技术路线、判定与实现

本文说明整机怎么跑、等级怎么算、词表在哪。规则只放在 `skills/`，板子不存关键词。

**不做：** 真假药鉴定、国家认证结论。绿灯只表示「眼前这段文字里没有堆足够的推销/诈骗话术」，不是药检合格。

---

## 1. 技术路线（一句话）

板子负责拍、听、按，并用大色块显示等级；电脑上的 Flask 把图/声变成字；**对错只在 `skills/` + `cloud/app.py` 的规则函数里算**。网页看板和板子走同一套 HTTP 字段（`docs/protocol.md`）。

```
老人  →  ESP32-S3-EYE（Arduino 固件 firmware/jianwei_eye/）
              │  JPEG / WAV / heartbeat JSON
              │  http://<电脑局域网IP>:8787
              ▼
         cloud/app.py
              │  RapidOCR 或 faster-whisper
              ▼
         文本
              │
              ├─ 验真 → verify_text()   （备案号 + 价格 + 夸大 + 渠道 + 词表减权）
              ├─ 守护 → guard_text()   （词表 + 组合拳 + 索要验证码）
              └─ 求助 → 不读文本，只认长按 BOOT ≥0.8s
              ▼
         level: high | mid | low   分数 ≥70 / ≥35 / 其余
              │
              ├─ 板子 LCD：HIGH / CHECK / OK（求助 HELP）
              └─ 子女网页：中文等级、原文、建议、事件列表
```

同一产品的另外两处代码（未作为周二现场主路径）：

| 实现 | 目录 | 现状 |
| --- | --- | --- |
| Arduino 回退（演示用） | `firmware/jianwei_eye/` | 已联调 |
| openvela 应用 | `app/jianwei/` | 协议对齐，未编烧 |
| 云端 | `cloud/` | 已跑，端口 8787 |

改规则：改 `skills/`（以及下文标明写在 `app.py` 里的短语表）。不要在 `.ino` 里复制词表。

## 2. 硬件与感知实现

开发板：乐鑫 **ESP32-S3-EYE**（OV2640 + ST7789 240×240 + I2S 数字麦）。原版 **没有扬声器**（`BSP_CAPS_AUDIO_SPEAKER = 0`）。等级主要靠屏上色块；网页已关闭自动朗读。

### 2.1 按键与模式

- **BOOT = GPIO0**，内部上拉：
  - **短按松开（≥40ms，<0.8s）**：立即切换验真 ↔ 守护（不再等 1.2s 连按窗口）。
  - **长按 ≥0.8s**：求助子女（按住约 0.8s 屏显 `HELP/HOLD..`，松开确认），并取消正在排队的拍照/听音。
- **LED = GPIO3**：验真模式常亮。
- 进入验真：延时约 **1s** 再拍（屏上 `AIM`），丢掉前两帧再取 JPEG。
- 进入守护：屏上 `TALK`，录音直到再次短按 BOOT 或最长约 **8s**，再上传。

固件入口：`firmware/jianwei_eye/jianwei_eye.ino`  
外设：`firmware/jianwei_eye/jianwei_hw.h`（相机、LCD、麦、PWM 试音 GPIO38）  
Wi-Fi / 云端地址：本地 `secrets.h`（勿提交）。

### 2.2 拍照

- 像素格式 JPEG，帧大小 VGA，质量约 8。
- 先在屏上解码显示（`jpg2rgb565` 缩放后居中裁 240×240），底部条 `WAIT`，出结果后改 `HIGH` / `CHECK` / `OK`。
- `POST /api/verify-image`，`Content-Type: image/jpeg`，超时 90s。
- 云端把图存为 `cloud/data/last_pack.jpg`，网页 `/api/device/photo` 可预览。

### 2.3 录音

- I2S：SCK=41，WS=42，SD=2，16 kHz。
- 立体声收满后按能量选左右声道，压成 16-bit 单声道 WAV，并做峰值放大。
- `POST /api/guard-audio`，`Content-Type: audio/wav`。
- 云端另存 `cloud/data/last_guard.wav` 便于排查。

### 2.4 本机读图（OCR）

文件：`cloud/local_recog.py`

- 引擎：RapidOCR ONNX（`rapidocr-onnxruntime`）。
- 调用时 `text_score=0.25`（默认 0.5 会把板端小图几乎全部丢掉）。
- 多视图：原图、必要时 2× 放大、顺时针/逆时针 90°，取最长文本。
- 本地有字则 **不再死等** 云端视觉。本地全空才尝试视觉接口（依赖密钥；不稳定，不作为主路径）。

### 2.5 本机听写（ASR）

- 引擎：faster-whisper `small`，优先 CUDA int8/float16，失败回 CPU。
- `language=zh`，**关闭 VAD**（远场小音量否则整段被当成静音）。
- 先算 PCM RMS/峰值：过静直接「没听清」，不跑模型。
- 当前 **不再串慢的云端 ASR**，避免板子超时重发。

模型缓存走 Hugging Face 镜像；需设 `HF_HUB_DISABLE_XET=1`，否则可能 401。

### 2.6 云端进程

- `cloud/app.py`：Flask，`0.0.0.0:8787`，`threaded=True`，`debug=False`。
- 启动时后台 `warmup()` 加载 OCR 与 Whisper。
- 只开 **一份** 云端。网页约 1s 轮询 `/api/device`、`/api/events`。

## 3. 协议（板子 / 网页 / 将来的 openvela）

基址：`http://<电脑局域网 IPv4>:8787`。板子不要用 `127.0.0.1`。

| 方法 | 用途 |
| --- | --- |
| `POST /api/verify` | JSON `{text}`，纯文本验真 |
| `POST /api/verify-image` | 原始 JPEG 或 multipart `image` |
| `POST /api/guard` | JSON `{text}`，纯文本守护 |
| `POST /api/guard-audio` | 原始 WAV 或 multipart `audio` |
| `POST /api/device/heartbeat` | `{mode, help}`；`help:true` 为求助 |
| `GET /api/device` | 看板：在线、模式、最近结果、照片时间戳 |
| `GET /api/device/voice` | 最近一次成功结论的 TTS WAV（失败档不合成） |
| `GET /` | 子女看板 |

板子从 JSON 里取 `level`、`level_label`、`advice`。完整中文理由只在网页。

## 4. 等级怎么从分数来

`cloud/app.py`：`score_to_level()`

| 分数 | `level` | 网页 | LCD |
| --- | --- | --- | --- |
| ≥ 70 | `high` | 高风险 | 红 `HIGH` |
| ≥ 35 | `mid` | 需核实（听不清时文案是「没听清」） | 橙 `CHECK` |
| ＜ 35 | `low` | 未见明显风险 | 绿 `OK` |
| 长按求助 | （事件 `kind=help`，分数 90） | 求助 | 品红 `HELP` |

分数上限 100。听不清也标 `mid`，所以是橙灯而不是绿灯。

## 5. 判定总览：不全是关键词

| 路径 | 判定方式 |
| --- | --- |
| 守护（听清之后） | 规则初判 + **Skill+LLM**（有 `OPENAI_API_KEY` 时） |
| 验真 | 多路规则初判 + **Skill+LLM**；识图用 Vision 模型抄录后再判定 |
| 没听清 | **不是关键词**：能量过低 / 无中文 / 听写为空 |
| 求助 | **不是关键词**：只认长按 BOOT ≥0.8s |
| OCR / ASR | **不是最终判定**：把图和声变成字，再交给规则 + Skill |

词表文件：`skills/keywords.json`（仓库内维护的规则，不是模型自己学出来的）。命中方式是 **子串包含**（`词 in 文本`），不是分词。

配置：`OPENAI_CHAT_MODEL` 负责 OCR/ASR 后的文本理解（引擎 `skill+llm`）；`OPENAI_VISION_MODEL` 负责包装识图。二者分开，避免把 VL 模型误用于纯文本时整段跳过 LLM。

### 6.2 组合拳（+40）

JSON 里的 `combo_rules` 是说明；**真正执行**在 `keyword_hits()` 末尾。三类必须 **同时** 出现：

1. **紧急**：立刻、马上、现在就、紧急、来不及  
2. **要钱**：转账、汇款、安全账户、打款  
3. **隔离核实**：不要告诉、不许说、不让子女、保密、不准问  

命中记作 `组合:紧急+要钱+不让核实`。

演示句「公安局、卡要冻结、立刻转到安全账户、不要告诉儿子」会叠多个单词分再加 40，顶到 100 → 高风险。

### 6.3 守护额外：索要验证码（+25）

文本含「验证码」，且含「告诉我」或「念给我」或「发给我」。

### 6.4 守护之后的话术

`skills/scripts.md`，按档抽取：

- **high**：安抚 → 核实（通讯录回拨）→ 暂缓转账 → 报案 110 / 96110  
- **mid**：安抚 → 核实  
- **low**：尚未出现典型组合，对方催转账可再听一次  

脱身、止损段落给模型/Skill 用，板子屏上不显示长文。

## 7. 验真判定（多路，不只关键词）

实现：`verify_text()`。OCR 文本进入后按下面累加。

### 7.1 备案号 `check_license()`

正则（演示用，非官方全集）：

- `国食健注G/J` + 8 位数字  
- `食健备` + 省名或字母 + 数字串  
- `国药准字` + 字母 + 8 位数字  

说明见 `skills/license_rules.md`。

| 情况 | 加分 |
| --- | ---: |
| 出现「内部批文 / 内部号 / 内部编号 / 特批」且没有正经号 | +35 |
| 对上正则但含「内部」，或 `国食健注` 位数不对 | +35 |
| 完全没有备案号 | +10（普通超市包装常走这条，通常仍不够红） |
| 格式像常见备案号 | +0，备注「仍须自行在官网核对」 |

**禁止**输出「已通过国家认证」。

### 7.2 价格带 `check_price()` + `skills/prices.json`

必须 **品类名（或别名）和「数字+元」同时出现** 才比较，否则跳过。

| 品类 | 别名 | 演示区间 |
| --- | --- | --- |
| 钙片 | 钙、补钙 | 20–180 元/瓶 |
| 蛋白粉 | 蛋白质粉 | 80–400 元/罐 |
| 灵芝孢子粉 | 孢子粉、灵芝 | 50–600 元/盒 |
| 阿胶 | — | 80–800 元 |
| 助听器 | — | 200–8000 元 |
| 血压计 | — | 80–600 元 |

超出区间 **+25**。区间是演示用经验带，不是官方限价。

### 7.3 夸大宣传 `hype_hits()`（写在 `app.py`，不在 JSON）

下列短语每个 +10，合计最多 +30：

包治、根治、药到病除、祖传、国家级、纳米、基因修复、当天见效、无效退款、医院不告诉你、内部指标、限时抢

### 7.4 购买渠道 `channel_risk()`

按表 **从上到下命中第一项** 即返回：

| 词 | 分 | 记作 |
| --- | ---: | --- |
| 讲座 | 25 | 讲座推销 |
| 免费旅游 | 25 | 免费旅游/旅游团 |
| 旅游团 | 20 | 旅游团 |
| 微信群 | 15 | 微信群 |
| 专家 | 10 | 专家推荐话术 |

### 7.5 关键词在验真里减权

`min(keyword_hits分数 / 2, 20)`，避免电话诈骗词把一盒普通药直接打红。验真主战场是备案号、价格、夸大、渠道。

### 7.6 验真建议与追问

建议按档写死：

- high：先不要付款；备案号到市场监管相关查询页核对并告诉子女  
- mid：记下编号和价格，回家和家人查；讲座限时先别信  
- low：文字里没有特别夸张的承诺；仍建议正规店购买并留小票  

追问来自 `skills/verify_followups.md`：在哪买的、是否先交钱再领礼品、备案号能否念、有没有不让告诉子女。

## 8. 听不清与求助（不走词表）

**听不清（固定 `mid` / CHECK）**

- WAV 太短  
- RMS 与峰值过低（几乎没声）  
- Whisper 无字  
- 结果几乎没有汉字或不足 4 字  

文案引导贴紧板侧麦孔、说完再按 BOOT。不给 `low`。

**求助**

心跳 `help: true` → 事件 `kind=help`，建议用 `scripts.md`「求助确认」。不分析录音内容。

## 9. 状态对照（汇报时可用）

1. **验真绿 OK**：有字，但备案/价格/夸大/渠道/减权关键词合计 ＜ 35。  
2. **验真橙 CHECK**：有可疑点但 ＜ 70。  
3. **验真红 HIGH**：内部批文、天价、包治/讲座等叠到 ≥ 70。  
4. **守护红 HIGH**：词表 + 组合拳和/或索要验证码 ≥ 70。  
5. **守护橙 CHECK**：有词但不够 70，**或没听清**。  
6. **守护绿 OK**：听清了但几乎未命中表。  
7. **HELP**：只认长按 BOOT ≥0.8s。
